# Fidelity

Every place where this port could differ from upstream ACDC, and the flag
that controls it. **Defaults reproduce the Fortran**, always. Each row gets
a test at both settings.

The governing rule (`CLAUDE.md`): port from the code, not the comments, and
not the manual. Where the three disagree, the generated Fortran wins.

## Upstream quirks reproduced by default

| F1 | **Fitted-`c` projection.** Fortran assigns the residual to the monomer and rescales multiplicatively *only* if that would go negative. MATLAB **always** rescales. Different distributions from the same constraint. | `driver_acdc_J.f90:405-410` vs Perl `:10336-10344` | `fitted_projection` | `"fortran"` |
| F2 | **Charge balance.** MATLAB applies an explicit algebraic projection on the generic ions each outer iteration. The *default* Fortran has none and relies on symmetric ion sources. The generator's `--charge_balance ±1` flag emits the same projection into the Fortran `feval`/`formation` (fixture `acdc_equations_cb1.f90:93-99`): one generic ion becomes algebraic (`isconst`, source dropped) and is set so total positive equals total negative charge, with the other ion clamped from below at zero. Ported as `charge_balance` in `FidelityConfig` and `rhs.assemble`; validated on the emitted algebra at 1e-13. | Perl `:2135-2180`, `:10346-10377` | `charge_balance` | `0` |
| F3 | **Steady-state tolerance disagrees three ways:** Fortran `sstol=1e-5`, MATLAB `difftol=1e-3`, manual documents `1e-5`. | `solution_settings.f90:20` vs Perl `:10041` vs manual §4.3.2 | `sstol` | `1e-5` |
| F4 | **Negative J is silently clamped** to `1e-100` rather than reported. | `get_acdc_J.f90:117` | `clamp_negative_j` | `True` |
| F5 | **Non-convergence is indistinguishable from J=0.** Upstream returns `j_out=0` with `ok=.true.` on steady-state failure. | `driver_acdc_J.f90:178-187` | — | we return an explicit status; the numeric result is unchanged |
| F6 | **Warm start.** `c` and `t_iter` are `save`d across plugin calls, so identical inputs give different outputs — **measured at 1.5e-6 relative in J**, while a cold start is bit-identical across processes. This is why the J gate is 1e-5, not 1e-6; see `docs/validation.md`. | `get_acdc_J.f90:31,42` | — | we thread state explicitly; pure by construction |
| F7 | **Hydrate distributions whose normalised sum is not above 0.99 are silently discarded** and the cluster treated as dry (Perl `:2432-2440`). Since the sum of normalised weights is 1 by construction, the check can only fail on a non-finite distribution (an overflowing Boltzmann factor gives NaN, and `NaN > 0.99` is false) — so in practice a hydrate that is *too* stable makes upstream quietly ignore all of that cluster's hydrates. Reproduced: `hydrate_weights` applies the same guard. | Perl `:2432-2440` | `hydrate_discard_threshold` | `0.99` |
| F8 | **ACDC's physical constants** differ from CODATA-2018 in the last digits (`k_B = 1.3806504e-23`, `N_A = 6.02214179e23`). | Perl `:924-928` | `constants` | `"acdc"` |
| F9 | **`ind_quad_loss_extra` is built but never read** by `feval`; the extra-product source is applied from the product's side. | `acdc_equations_*.f90:89-124` | — | reproduced (built, unused) |
| F10 | **No van der Waals or Fuchs correction** on hard-sphere collisions; a vdW enhancement exists commented-out upstream. | Perl `:8798` | — | reproduced |
| F23 | **Two-component loop mode does not compile.** `get_masses_and_radii` builds its mass and volume sums with a `+` after every term and a line continuation after every second one; the trailing-`+` strip (`s/\+$//`, Perl `:6266`) runs *after* the continuation is appended, so with two used types out of a longer header the emitted line reads `...*m2+&` `&)` — a syntax error. One-component systems are unaffected. The f2py oracle closes the sum before compiling; the port computes the sums directly. | Perl `:6252-6270` + `_loopAN66` fixture | — | n/a |
| F22 | **One-component loop-mode `feval` reads `E(j,i)` out of bounds.** `E` is declared `E(nclust,1)` (monomer evaporation only) but the pair loop tests `E(j,i) .gt. 0` for every `i ≤ j`, so `i ≥ 2` indexes past the single column; `-fcheck=bounds` traps at once. In the gfortran builds tested the reads happened to land on zeros, so results were unaffected, but that is luck, not semantics. The oracle widens `E` to `(nclust,nclust)` so the reads are genuine zeros; the port stores the full symmetric matrix. | Perl `:4404` vs `:4591` + `_loopA20k` fixture | — | n/a |
| F21 | **Loop mode with coagulation, wall loss and dilution all enabled emits invalid Fortran.** `get_losses` ends in `loss = cs+ wl, dil`: the generator joins the loss names by turning commas into plus signs with a single, non-global substitution (Perl `:7667`), so three losses leave one comma behind and the file does not compile. Any two losses work. Not reproducible by construction; the port sums whatever losses are selected. | Perl `:7664-7668` + `_loopA20all` fixture | — | n/a |
| F20 | **The Fortran drops the coefficient of a `--nst` line's first product.** `1N 2A1N 2 1A1N` parses the 2 into `coef_quad_form` (Perl `:2757-2768`), but only the MATLAB emitter reads that hash (`:4960`, §8.4 "dC/dt for Matlab"); the Fortran `feval` forms the main product once per collision via `ind_quad_form`, and the generated file has neither a `2.d0` nor an `ind_quad_form_extra` entry for it. Mass is not conserved: one 1A1N is formed and the other vanishes. Coefficients on the third column onward do land (`ind_quad_form_extra` with `n_quad_form_extra`), so `1 1A1N 1 1A1N` is the way to get two. Reproduced by default. | Perl `:2757`, `:4960` + `_nst`/`_nst2` fixtures | `nonstandard_main_coefficient` | `"fortran"` |
| F19 | **A sticking factor is applied to evaporation twice.** The generator prepends the `%.4e` factor literal to the `E(i,j)` expression (Perl `:9231`), which already ends in `*K(i,j)` — and `K(i,j)` carries the same literal (`:8458`). So `K ∝ s` but `E ∝ s²`, and `E/K` is no longer `exp(ΔG/kT)/n_ref`: the sticking factor shifts every equilibrium by `s`. Verified on the generated fixture: `E(3,1)` with `--sticking_factor 0.5` is 0.25× the plain value where `K(3,1)` is 0.5×. Reproduced by default; `detailed_balance` applies the factor once through K. | Perl `:8458`, `:9231` + fixture | `sticking_on_evaporation` | `"upstream"` |
| F17 | **The 2024 generator silently loosened the MATLAB `difftol` default 100× (1e-5 → 1e-3).** This is the *cause* of the three-way disagreement recorded as F3: the manual and the 2020 generator say 1e-5; the 2024 generator's emitted `driver_acdc.m` says 1e-3, with no caller override and no manual update. Found by the code-review agent when it (mis)targeted the upstream checkout. Affects MATLAB only; this port's Fortran-side `SSTOL = 1e-5` is unaffected. | `acdc_2024_02_12.pl:10041` | `sstol` | `1e-5` |
| F18 | **The 2024 generator's `%.4f` literals land as single precision.** Eleven `sprintf("%.2f")`→`"%.4f"` sites are followed by `s/e/d/`, but `%.4f` never emits an `e`, so the substitution is a no-op and the literals are default-`REAL` constants assigned into `real(kind(1.d0))`. For masses ≳1000 amu the added 4th decimal is rounded away. Does not affect this port (we never round to emit) and does not affect the 2020-generated shipped example. Recorded because it explains why the committed files carry `%.2f` values. | `acdc_2024_02_12.pl:3951` | — | n/a |
| F16 | **The `diffusion` wall loss excludes the generic charger ions; no other loss does.** In the 2020 generator — the one that produced the shipped example and every golden here — that branch alone loops `for iclus = 1 .. $max_cluster` (the real clusters) where every other loss branch loops to `$max_cluster_number`, which includes the two generic ions; the fixture has exactly 52 nonzero entries. The 2024 generator loops to `$max_cluster_number` and gives `neg`/`pos` a diffusion loss too (`capture_variants.py` cross-check: the only variant where the two generators differ). Default reproduces the shipped Fortran; the flag selects the 2024 behaviour. | Perl 2020 `:7325` vs e.g. `:7159`; 2024 `:7874` | `diffusion_wall_loss_generic_ions` | `"excluded_2020"` |
| F15 | **`--ion_coll_method constant` is a no-op under variable temperature.** The manual documents a size-independent enhancement of 10. At fixed temperature upstream applies it; with `--variable_temp` it is silently dropped and every ion–neutral pair emits the bare hard-sphere rate — verified by generating the fixture (0 of 587 pairs enhanced, no `10.d0` anywhere in `get_coll`). Someone using it for a quick variable-temperature run gets collisions 5–17× too slow with no warning. Exposed as two explicitly-named options rather than one silent default. | Perl `:8267-8271` sets `10.d0`; `:8436` excludes `constant` from the `max(fcr, hard sphere)` emission, so the value string falls through to bare hard sphere. Fixed-T fixture `constant_fixed` shows the factor applied; variable-T fixture `constant` shows it dropped | `ion_collision_method` | `"su82"` |
| F14 | **The integrator's absolute tolerance is loosened.** The reference uses `atol = 1e-6` m⁻³ = 1e-12 cm⁻³; VODE's BDF tolerates that because it rescales internally, but Kvaerno5 exhausts a 20,000-step budget on the evaporation-dominated corner of the grid. This port uses 1.0 m⁻³ — still six orders below any meaningful concentration. J is measured identical from atol 1e-6 to 1e4, so nothing physical rides on it; `test_solve.py` asserts that insensitivity. | `solution_settings.f90:9` | `atol` argument | `1.0` m⁻³ |
| F13 | **The root-find path under-reports convergence.** Its relative residual `f/c` floors near 6e-5 because at steady state `f` is a small difference of large opposing fluxes, so optimistix never certifies even though J is correct to 2e-6 and matches the integration path to 2e-9. Gate on the inter-path agreement, not the flag. | — | — | known limitation |
| F12 | **The ion-neutral enhancement exceeds the manual's stated range.** The manual describes it as "a factor between one and ten"; measured on the reference's own `get_coll` at 280 K it runs 1.17–16.95, with 6% of ion-neutral pairs above 10. The manual is an approximate characterisation, not a bound the code enforces. Reproduced (there is nothing to fix); asserted in `test_rates.py` so a future clamp would fail. | manual §2.5.1 vs Perl `:8853-8888` | — | reproduced |

## Structural differences (not configurable)

These are the point of the port; they are not divergences to be flagged but
capabilities the reference lacks.

| Difference | Reference | Here |
|---|---|---|
| Jacobian | empty `jeval`, VODE `mf=22` finite differences, `neqn` extra RHS calls per build | `jax.jacfwd`, exact |
| Rate constants | 9585 lines of emitted numeric literals, frozen per outer call | traced functions of `T` |
| Temperature branches | `(.5±sign(.5,T−T0))` branchless Heaviside, because Perl could not evaluate the branch at generation time | one `jnp.where` |
| `j_by_cluster`, `j_all` | computed by `formation`, discarded by the driver | returned |
| Net-flux matrix | MATLAB only (`dofluxes.m`) | native, ~free from the RHS einsum |
| Rate recomputation gate | `ipar` mutated through the ODE solver as a hidden side channel | immutable params pytree |
| Cluster set changes | regenerate Fortran with Perl, recompile | parse a data file |
